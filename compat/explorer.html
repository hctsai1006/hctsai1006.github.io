PowerShell 7.7.0-preview.4 is built on the .NET 11.0.100-preview.6 runtime.

  • 7.7.0-preview.4

    A release. Confirmed against the Releases API, and against the commit its annotated tag actually dereferences to.

  • 11.0.100-preview.6

    Not a runtime. This is the SDK version. The runtime that SDK ships is 11.0.0-preview.6.26359.118 — the two differ in the third component, the SDK feature-band level, which a runtime version does not have.

  • “runtime”

    Wrong noun. SDK and runtime are separate version spaces. No string edit converts one into the other; only the .NET release metadata relates them.

One sentence, three claims, two of them imprecise. It is not a careless sentence — it is what happens when one string has to carry facts that move independently. So this workstation does not store a version. It stores where every version came from, and what disagrees — and of the four differences it currently records, none are emulated yet.

What it was built on

Five axes drift independently — which releases exist, which commit a tag is, which SDK it pinned, which runtime that ships, what .NET has since shipped. Reading any one of them as “the version” produces a confident wrong answer, which is what the sentence at the top of this page does.

SDK pinned by the tag 11.0.100-preview.6.26359.118
the runtime it ships 11.0.0-preview.6.26359.118

A lookup, not a comparison. The SDK feature-band level (100) and the runtime patch (0) are unrelated numbers, and only the .NET release metadata connects the two.

changes are emulated. The rest are recorded and cited, but the engine does not reproduce them yet. Nothing here claims fidelity a test has not demonstrated.

  • New-Guid#27033

    New-Guid emits a time-sortable UUID v7 by default instead of a random UUID v4

    The output type and format are unchanged, which is what makes this dangerous: a script keeps working, but its identifiers become predictable. Time-ordered UUIDs leak creation time and are guessable in sequence, so anything using New-Guid as a secret or a nonce becomes weaker without any visible change.

    To migrate. A script that needs a fully random GUID must call [guid]::NewGuid() directly rather than New-Guid. Never use either as a security token: use a CSPRNG.

    script breaking not emulated

  • Format-Table, Format-List, Format-Custom#26552

    ValidateNotNullOrEmpty added to -Property

    Confirmed against the reference implementation: Format-Table -Property carries no validation attributes in 7.6.5, so passing an empty string succeeds there and throws in 7.7.

    To migrate. Filter empty values out of a -Property list before passing it.

    script breaking not emulated

  • argument validation#26668

    Not-null-not-empty validation now throws ArgumentException instead of PSArgumentNullException

    The exception type changes from System.Management.Automation.PSArgumentNullException to System.ArgumentException, so a catch block filtering on the old type stops matching.

    To migrate. Catch System.ArgumentException, or catch both types during a migration window.

    script breaking not emulated

  • Where-Object#26485

    Explicit -<Operator>:$false is now honoured rather than treated as present

    A switch parameter written as -Not:$false was previously indistinguishable from -Not. This is the general shape of a whole family of 7.7 fixes and is why the binder must model switch semantics rather than mere presence.

    observable not emulated

  • New-TemporaryDirectory#27549

    New-TemporaryDirectory cmdlet added

    Makes a temp directory a first-class concept, which means the virtual filesystem needs a real /tmp provider rather than an ordinary directory that happens to be named tmp.

    no impact not emulated

  • Format-Table, Format-List, Format-Custom#26514

    -ExcludeProperty parameter added to Format-* cmdlets

    Confirmed absent in 7.6.5 by the captured command metadata. Belongs to the formatter, which is why formatting has to be separable from the command.

    no impact not emulated

  • Join-Path#26482

    -Extension parameter added

    Confirmed absent in 7.6.5 by the captured command metadata.

    no impact not emulated

  • $PSApplicationOutputEncoding#21219

    Automatic variable controlling how native command output is decoded

    Requires an encoding broker between the object pipeline and the native byte pipeline: without one, native output is decoded once, wrongly, and cannot be recovered.

    observable not emulated
