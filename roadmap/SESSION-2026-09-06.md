## The decision that is owed first

**Two textareas.** Both renderer streams found this independently and neither
resolved it, correctly — it spans both seams.

`xterm.js`'s `Terminal.open(parent)` installs its own hidden `<textarea>` with
its own IME path and key listeners. `TextareaInputAdapter` writes `surface.value`
and calls `setSelectionRange`. If the xterm adapter is ever attached to a real
DOM, the two compete for focus and for the composition, and it cannot be both.

Nothing is wired today: `TerminalPort` has no input surface at all, and a test
fails if the adapter touches `onData`, `onKey` or `textarea`. So this is not
broken — it is undecided, and it must be decided before either side touches
`index.html`. One option already noted: `@xterm/headless` has no `open()` at all.

### Language and kernel (PR-8)

- `$x [int]` and `$x (1)` are `UnexpectedToken` in pwsh but come back named
  `TypeExpressionAst` / `ParenExpressionAst`. Refusals with a name one step too
  generous, not things that wrongly run. Fixing it means deciding which of ~40
  token kinds continue an expression, which this parser deliberately does not
  answer.
- Refusal volume is uncapped on purpose, because pwsh reports every parse error
  with no cap. Measured: 64 KiB of `$a;` yields 21,845 refusals and 6.6M
  characters in one `rejected` event; it clones in 23 ms, so it crosses, and a
  host rendering one line per problem is what will suffer.
- The wire ceiling is exactly **4,194,152 JSON characters**; 4,194,153 is
  refused. That is 148 below what the string charge alone allows, because the
  record's own type and property names are charged first — so an assertion
  computed from the formula agrees with the wrong number.

  synthetic adversary, and says so.

## Corrections this session made to its own earlier claims

Recorded because each was stated confidently and was wrong, and the same
reasoning would produce them again.

- `formatResolved` claimed pwsh renders a provider drive with backslashes "on
  every platform". That was a Windows-only measurement. On `pwsh-linux:7.6.5` the
  location is `Env:/`. The emulated machine is Ubuntu, so the rendering is `/`.
- Error messages do not always echo the path as typed: `-Path` normalises
  (`Env:\NoSuchVar`); only `Set-Location` and `-LiteralPath` echo it verbatim.
- The unimplemented AST node list is **40**, not the 37 one branch shipped nor
  the 22 a briefing asserted. `CommandAst` had been published as unimplemented,
  though every command the engine runs is one — the list derived from message
  names rather than from refusals.
- The EPIPE crash in #8 was described as arising from a POSIX-specific fix. It
  was never POSIX-only: Windows reports EPIPE too, errno -4047 rather than -32.
